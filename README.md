## 这个项目是什么

一台**沿着黑线逆时针绕场**、并带一台 **OpenMV4 摄像头找气球**的四轮小车：

```
Arduino UNO  ──  巡线：直行进场 → 右转并线 → PD 巡线 → 4 个左弯 → 全白刹车停车
OpenMV H7+   ──  辨色：找最近的「非红」气球 → 把水平偏移/大小/距离送给 UNO
                 （红球要躲：规则里扎破红球 = 比赛立即终止）
```

赛道是一条**没有岔路的闭环**，四个直角弯全部是左弯；第 4 个弯之后线走完（灰段约 25cm），
车停在线尾。按最初的设计，停车之后应该「左转进场」去扎气球，但现在这一段还是 **WIP**（见[项目现状](#项目现状先看完成度)）。

气球相关的规则（摘自代码注释，仅供参考）：

- 场地里是**马卡龙气球**（粉彩色，明度 L 高、饱和度 A/B 都不大），最大直径 160~200mm，程序按 18cm 估算；
- 扎破红球 = 立即终止比赛，所以红球单独一组阈值，**宁可把别的颜色当红球**；
- 橙色可能出现，且和红色在 LAB 里很接近——主要靠 **B 通道**分开（橙色 B 高、玫红 B 不高）；
- 把非红球判成红球的代价是「漏扎一个，加时 60 秒」，和误扎红球不是一个量级。

## 系统架构

```
                    ┌──────────────────────────────┐
                    │      OpenMV4 H7 Plus         │
                    │  balloon_core.py（算法/参数） │
                    │  main.py（= balloon_main.py） │
                    └──────────────┬───────────────┘
                                   │ UART3  115200
                                   │ P4=TX → UNO RX
                       P5=RX ←─────┘（UNO TX，只有需要回传时才接）
                                   │
                    ┌──────────────┴───────────────┐
                    │         Arduino UNO R3       │
                    │  巡线 PD + 左弯 + 终点控制     │
                    └───┬───────────┬──────────┬───┘
                        │           │          │
                  A1/A2 巡迹      D2/D6       D4/D5
                  （左/右）      左侧轮组     右侧轮组
                                   │
                             Keyes L298P 扩展板
                              A 通道 ── 左前 + 左后（并联）
                              B 通道 ── 右前 + 右后（并联）
```

两条链路是**物理独立**的：巡线只用两个红外探头，辨色只用摄像头，唯一的交集是 UART 上的一串帧。

### 硬件清单

| 部件 | 型号 / 说明 |
| --- | --- |
| 主控 | Arduino UNO R3 |
| 电机驱动 | Keyes L298P 电机驱动扩展板（KE0163） |
| 电机 | 4 个直流减速电机，左右各 2 个 |
| 巡迹传感器 | 2 路（手头模块是 3 路，第 3 路不用） |
| 摄像头 | OpenMV4 H7 Plus，2.8mm 镜头（HFOV ≈ 70.8°） |
| 电源 | 7~9V 电池组（**不要只靠 USB 供电**，电机一转就拉低电压） |

### 接线表

巡线与电机：

| 信号 | 引脚 | 备注 |
| --- | --- | --- |
| 巡迹 S1（左） | A1 | 当数字口用 |
| 巡迹 S2（右） | A2 | 当数字口用 |
| 巡迹 V / G | 5V / GND | |
| 左侧两轮 | A 通道：方向 D2 / 调速 D6 | 组内并联，只能同步 |
| 右侧两轮 | B 通道：方向 D4 / 调速 D5 | 组内并联，只能同步 |

> 这张表按 `pd_v3.0+1.01.ino`（`A_CHANNEL_IS_LEFT = 1`）和 `car_straight.ino` 写。
> `motor_test.ino` 的注释把 A 组记成右侧，**两者矛盾，以四个轮子的实际转向为准**（见[已知的坑](#已知的坑)第 1 条）。

摄像头与 UNO：

| OpenMV | UNO | 说明 |
| --- | --- | --- |
| P4（UART3 TX） | RX（软串口 D8 或硬串口，取决于 UNO 侧程序） | 必须共地 |
| P5（UART3 RX） | TX（可选） | 只有 UNO 需要回传时才接 |
| GND | GND | **必接**，不共地会收到乱码 |

> - UART 参数：`115200`。若 UNO 侧用软串口（D8/D9），两边都要降到 `38400`。
> - **P4/P5 同时是 I2C2 和 UART3，二选一，不能同时用**。代码里由 `LINK = "uart" / "i2c"` 切换。
> - 走 I2C 时：P4=SCL、P5=SDA，UNO 当从机，地址 `0x08`。

## 快速上手

### Arduino 侧：按顺序烧录

按这个顺序，**每一步确认通过了再走下一步**，不要跳：

| 顺序 | 程序 | 目的 | 通过标准 |
| --- | --- | --- | --- |
| 1 | `line_sensor_test.ino` | 确认"检测到黑线"输出的是高电平还是低电平 | 探头贴白纸按 `w`、贴黑线按 `b`，串口给出结论 |
| 2 | `motor_test.ino` | 四轮转向、调速是否正常（**先架空**） | 前进/后退/原地转方向都对；爬坡不堵转 |
| 3 | `car_straight.ino` | 整车直线跑一段（**先架空**） | 四轮同时正转 |
| 4 | `pd_v3.0+1.01.ino` | 上车跑完整赛道 | 数满 4 个左弯、到线尾刹停、D13 闪 2 下 |

第 1 步的结论要回填到 `pd_v3.0+1.01.ino`：

```cpp
#define BLACK_LEVEL HIGH   // 检测到黑线输出高电平填 HIGH，低电平填 LOW
```

第 4 步的几个关键前提：

- `PROBES_CENTERED_BOTH_ON_LINE` 必须和实际装法一致（本车两探头间距 12mm < 线宽，骑在线上时两路都压线 = `1`）；
- `A_CHANNEL_IS_LEFT` 决定左右轮，接反了车会画龙甚至原地打转；
- `START_DELAY_MS` 是上电后等待时间，默认 2000ms，留给你把车摆进出发区。

**停车后看 D13 闪几下**：

| 闪烁次数 | 含义 |
| --- | --- |
| 1 闪 | 总时间保护触发（`RUN_SAFETY_TIMEOUT_MS` 默认 90s） |
| 2 闪 | 正常终点（回到出发区/线尾） |

| 顺序 | 脚本 | 目的 | 通过标准 |

### 上车部署（摄像头）

**两份文件，顺序别反**：

1. OpenMV IDE 打开 `balloon_core.py` → 菜单 `工具(Tools)` → `Save open script to OpenMV Cam`；
2. 再打开 `balloon_main.py` → 同样存进去，**存成 `main.py`**；
3. 弹出 USB 磁盘 → 拔线 → 给车通电。冷启动会自动跑 `main.py`。

> - **只存了 `main.py` 会报 `ImportError`**：灯狂闪 + IDE 里会打印中文提示。补存 `balloon_core.py` 即可。
> - 摄像头里**只能有一份 `main.py`**：存成 `main.py` 之后摄像头就专职辨色，不再巡线；巡线归 UNO 管。
> - 调参只改 `balloon_core.py` 的参数区，所有 import 它的入口脚本自动生效。

上电自检灯语：

| 现象 | 含义 |
| --- | --- |
| 蓝灯慢闪 2 下 | 链路自检通过（**UART 模式下这一步永远通过**，见下方说明） |
| 红灯快闪 8 下 | 没找到 UNO（I2C 模式才判得出来），但**程序会继续跑** |
| 中途发送失败（I2C / UART） | 只累加错误计数，不崩、不停 |

> UART 没有 ACK，"线接没接好"靠自检是看不出来的——`link_selftest()` 在 `LINK = "uart"` 时直接返回 `True`。
> 真正的联通要拿 USB-TTL 抓 P4 上的字节，或者看 UNO 侧收帧计数。

## 通信协议

### 气球帧（摄像头 → UNO）

固定 **10 字节**，帧类型字节 `0x56`，CRC 覆盖第 2~8 字节：

```
 0xAA  0x56 │ dx │ size │ flags │ ped_dx │ n_red │ dist │ seq │ crc
  帧头  类型 │  2 │   3  │   4   │    5   │    6  │   7  │  8  │  9
```

| 偏移 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| 0,1 | 帧头 | `uint8` | `0xAA 0x56` |
| 2 | `dx` | `int8` | **目标水平偏移** = 目标中心 x − 画面中心 x。正 = 目标在画面右侧。QQVGA 下范围 ±80，正好塞进 int8 |
| 3 | `size` | `uint8` | 目标外接框宽度（px），`0` = 本帧无目标。是距离的代理量 |
| 4 | `flags` | `uint8` | 见下表 |
| 5 | `ped_dx` | `int8` | 挡在正前方的红球偏移，只有 `F_RED_AHEAD` 置位时才有意义 |
| 6 | `n_red` | `uint8` | 画面里红球个数（调试用） |
| 7 | `dist` | `uint8` | 距离估计（cm），`0` = 估不出来 |
| 8 | `seq` | `uint8` | 帧序号，每帧 +1，0~255 回绕（UNO 用它查摄像头是不是卡死） |
| 9 | `crc` | `uint8` | CRC-8/ATM：多项式 `0x07`、初值 `0x00`、不取反 |

`flags` 位定义：

| 位 | 名称 | 含义 |
| --- | --- | --- |
| `0x01` | `F_TARGET` | 找到可扎目标（非红） |
| `0x02` | `F_RED_AHEAD` | **前方有红球挡路，别撞上去** |
| `0x04` | `F_RED_SEEN` | 画面里看到红球 |
| `0x08` | `F_NEAR` | 目标已经很近（宽度 ≥ 55px，≈37cm），可以撞了 |
| `0x10` | `F_NONE` | 本帧没有可扎目标（没球 / 只有红球） |
| `0x20` | `F_LOWCONF` | 低可信（预留，当前不置位） |
| `0x40` | `F_HOLD` | 本帧沿用上一帧的目标（短暂丢失保持） |
| `0x80` | `F_ERR` | 本帧异常（预留，当前不置位），UNO 应丢弃 |

### 与巡线帧共存

历史上还有一套巡线视觉帧 `0xAA 0x55`（9 字节），**产生它的那套视觉程序已经在 2026-10-17 整理时删除**，
现在仓库里没有发送方，只在协议上保留帧类型区分。UNO 侧收帧的正确姿势是：

```cpp
// 先找帧头 0xAA，再看 buf[1] 分派：0x55 = 巡线帧，0x56 = 气球帧
if (buf[0] == 0xAA) {
  if (buf[1] == 0x56) { /* 按 10 字节解析气球帧 */ }
  else if (buf[1] == 0x55) { /* 按 9 字节解析巡线帧 */ }
}
```

### CRC 校验

摄像头侧和 UNO 侧**必须完全一致**，改一边必须改另一边：

```c
uint8_t crc8(const uint8_t *d, uint8_t n) {
  uint8_t crc = 0x00;
  while (n--) {
    crc ^= *d++;
    for (uint8_t i = 0; i < 8; i++)
      crc = (crc & 0x80) ? (uint8_t)((crc << 1) ^ 0x07) : (uint8_t)(crc << 1);
  }
  return crc;
}
```

### 距离估算

```
dist(cm) = 球直径(18cm) × 焦距(112px) / 外接框宽度(px)
```

`FOCAL_PX = IMG_W / (2·tan(HFOV/2))`，2.8mm 镜头 ≈ 112。想更准就实测反推：

> 把球放在 30cm 处，读 `size`，则 `FOCAL_PX = size × 30 / 18`。

例：宽度 55px → 约 37cm；宽度 30px → 约 67cm。超过 `DIST_MAX_CM = 250` 一律按 250 报。

## 调参指南

### 巡线现象 → 改哪个宏

| 现象 | 先动这个 | 方向 |
| --- | --- | --- |
| 直道画龙（左右摆） | `KP` / `KD` | KP 调小或 KD 调大 |
| 弯道冲过头才开始转 | `CORNER_PRE_ENABLE` / `CORNER_LOST_CONFIRM_MS` | 开预判；确认时间调小（60→40） |
| 直道上误判成左弯 | `CORNER_LOST_CONFIRM_MS` | 调大（60→80/100） |
| 弯数数不满、一直绕圈 | `CORNER_REAL_MIN_MS` | 调小 |
| 转不干净、车头差 20~40° | `CORNER_TIMEOUT_MS` / `CORNER_PIVOT_INNER` | 时长加大；内轮更负（-120/-150） |
| 转过头了 | `CORNER_PIVOT_INNER` / `CORNER_TIMEOUT_MS` | 往回收（-60/-70）；时长减（350~400） |
| 出弯后车顺着旧线反着走 | `CORNER_MAX_RETRIES` / `CORNER_TIMEOUT_MS` | **别加大**，这两个是防"越拧越偏"的闸门 |
| 在弯里就刹停了 | `FINISH_ARM_MS` | 调大 |
| 到终点不停 | `FINISH_WHITE_MS` / 检查 `g_finishArmed` | 调小；确认第 4 弯真的计数了 |
| 车跑一半突然停 2 秒又从头来 | 电池 / `CORNER_OUTER_SPEED` | 内轮反转 + 外轮 210 是电流最大的一拍，弱电池会把 UNO 拉复位 |
| 电机嗡嗡响不转 | `MIN_SPEED` / 电池电压 | 低于死区会被直接当 0 |

### 辨色现象 → 改哪个参数

| 现象 | 先动这个 |
| --- | --- |
| 球明明在画面里却认不出来 | `TH_OTHER` / `TH_RED` 的 LAB 范围；确认 `LOCK_WHITE_BAL = True` |
| 红球被判成可扎目标 | 收窄 `TH_RED`；确认 `RED_IS_CONSERVATIVE = True`；检查 `LAB_RED_A_MIN` / `LAB_RED_B_MAX` |
| 橙球被判成红球 | `LAB_RED_B_MAX` 调小（橙色 B 高），或收窄 `TH_RED` 的 B 上界 |
| 框一直在抖 / 目标乱跳 | `CONFIRM_FRAMES` 调大、`HOLD_MS` 调大、`MIN_PIXELS` 调大 |
| 帧率太低 | 关 `DEBUG`、把 `X_STRIDE`/`Y_STRIDE` 调到 2（代价是会漏掉远处小球） |
| 白墙/地板反光被当成球 | 提高 `MIN_DENSITY`、`MIN_PIXELS`；检查阈值是否把 A≈0 B≈0 包进去了 |
| 距离估计不准 | 实测反推 `FOCAL_PX`（见[距离估算](#距离估算)） |

### 现场必须做的一件事：重标颜色

默认 LAB 阈值是按「白布 + 马卡龙气球」估的，**只能让你先跑起来**。标定流程：

1. 把球放在场地上，摄像头对着它，用 `live_view.py` 读画面中心的 `LAB = L… A… B…`；
2. 或者用 `balloon_detect.py`：把 `COLOR_SPACE` 改成 `"LAB"`、`TARGET` 改成 `"RED"`，它会打印每个 blob 的 LAB 均值
   （默认是 `"RGB"`，打印的是 RGB/HSV）；
3. 把对应颜色的 L/A/B 范围填进 `balloon_core.py` 的 `TH_RED` / `TH_OTHER`；
4. 记住分界线：**玫红 A 高、B 不高；橙色 B 很高**——红色和橙色主要靠 B 分开。

> 原作者注释里提到的标定脚本 `threshold_lab.py` **不在本仓库**，上面用 `live_view.py` 手动读中心 LAB 代替：
> 能用，但得自己拿小本本记数值，没有"命中哪个颜色 / 余量多少 / 建议阈值"那种提示。

## 已知的坑

这些是代码注释里反复强调、且真的会翻车的点：

1. **`motor_test.ino` 的 A/B 组注释和其他程序相反。**
   它写「A 组 = 右侧（M3/M4）」，而 `pd_v3.0+1.01.ino`（`A_CHANNEL_IS_LEFT = 1`）和 `car_straight.ino` 都把 A 当左侧。
   烧录测试时**以四个轮子的实际转向为准**，不要照抄注释。
2. **`line_sensor_test.ino` 是三路**（S1=A1、S2=A2、S3=D3），巡线程序只用两路。第三路留着不用即可。
3. **`MIN_SPEED = 60` 是硬死区**。`CORNER_PIVOT_INNER` 填 `-30` 是无效的——要么填 `0`，要么 ≤ `-60`。
4. **P4/P5 不能同时当 UART 和 I2C**。切换 `LINK` 时记得把 `car_balloon.ino` 那边一起改。
5. **UART 没有 ACK**。自检通过 ≠ 线接好了；接反 TX/RX、不共地都会静悄悄收不到。
6. **摄像头只能有一份 `main.py`**。`balloon_core.py` 忘了存 → ImportError + 灯狂闪。
7. **不要原地盲转过半圈**。`CORNER_TIMEOUT_MS` 是硬上限：转过 90° 后探头会扫到刚才那根线，
   车会顺着旧线反着走，越拧越偏。
8. **弱电池会表现成"程序 bug"**。内轮反转 + 外轮 210 那一拍电流最大，电压被拉低会导致 UNO 复位（车停 2 秒后从 setup 重来）。
9. **红球阈值宁窄勿宽**。误扎红球 = 直接判负，漏扎只是加时 60 秒。
10. **`arduino/` 下的 `.ino` 不能直接打开**，Arduino 要求同名文件夹（见[仓库结构](#仓库结构)的提示）。

## FAQ

### Q：OpenMV 上电没反应 / 灯一直闪，怎么办？
先确认 `balloon_core.py` 存进去了。只存 `main.py` 会 ImportError 并红灯狂闪。还不行就用 `minimal.py` 判断是代码问题，还是固件/IDE 版本不配套。

### Q：`TypeError: 'int' object isn't callable` 是什么？
OpenMV 4.x 的 `blob.w()` 是函数，5.x 的 `blob.w` 直接是整数。代码里用 `_bv()` / `_val()` 兼容层两种都吃。
如果自己新写了取值代码，记得也走兼容层。

### Q：为什么程序里到处是 `try/except` 和"出错不死"？
摄像头固件版本杂、现场线松、I2C 抖一下都很常见。宁可少一帧数据，也不要整段脚本崩掉、车停在场上。
`live_view.py` 就是"出错只打印一次，继续跑"的典型。

### Q：能不能不做气球的颜色判断，只按形状认？
可以，`balloon_detect.py` 的 `TARGET = "ANY"` 就是完全不看颜色，只过形状（比例/填充率/凸度/圆度）。
但注意：**比赛里必须区分红球**，所以真正上车还是得用带 `TH_RED` 的 `balloon_core.py`。

### Q：改了参数怎么快速验证？
- 巡线：先架空转轮子看方向，再低速（`BASE_SPEED` 降到 100）上赛道跑一段；
- 辨色：先跑 `live_view.py` / `balloon_detect.py` 看打印，确认能框住球再存 `main.py`。

### Q：为什么车停在线尾不进场？
因为进场那一段还没写（见 [WIP 清单](#wip待完成)）。当前 `pd_v3.0+1.01.ino` 的设计目标就是"跑完线、在线尾停车"。

### Q：这代码能直接拿去比赛吗？
**不能直接拿去比赛。** 至少要先完成：补接收端、补进场、现场重标颜色阈值、真车跑通全流程。
这也是本文档一开头就写"AI 生成、未经赛场验证"的原因。
